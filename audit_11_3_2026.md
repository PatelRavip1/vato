# Vato Voice Call & Audio Pipeline Audit (2026-11-03)

## Summary
Audited and resolved voice call functionality on Android emulator (`emulator-5554`, `pixel10proxl`, Android 16 API 36) connecting to backend `vato-proxy` (:8081) and local LLM `llama-server` (:8080).

## Issues Identified & Fixed

### 1. Hardcoded Server Reset & Localhost Erasure in Frontend
- **Issue**: `assets/index.html` contained legacy logic that overwrote `http://127.0.0.1:8080` or `http://127.0.0.1:8081` in `localStorage` back to `DEFAULT_SERVER` (`192.168.6.87:8081`), causing emulator network calls to timeout.
- **Fix**: Removed the forced overwrite block. Added `http://10.0.2.2:8081` (emulator host) and `http://127.0.0.1:8081` (reverse port forward) to `fallbacks` array in `checkConnection()`.

### 2. Live Call Overlay Status & Caption Elements Hidden
- **Issue**: `#liveStatus` and `#liveCaption` had inline `style="display:none;"`, preventing call state (`Listening…`, `Thinking…`, `Speaking…`) and speech transcripts from rendering in the live call bar.
- **Fix**: Removed inline `display:none;` and ensured class `live-status` and `live-caption` styles render properly.

### 3. Speech Engine Routing by Language
- **Requirement**: English must use SenseVoice ONNX STT on the backend; Gujarati must route to Android's native on-device `SpeechRecognizer` (`android.speech.SpeechRecognizer`).
- **Fix in `MainActivity.java`**:
  - Gated `startSenseVoiceRecording` strictly behind `"en".equalsIgnoreCase(locale.getLanguage())`.
  - Routed any non-English language (`gu-IN`) to `startNativeSpeechRecognizer(locale)`.
- **Fix in `server/sensevoice.py`**:
  - Pinned `language="en"` in `sherpa_onnx.OfflineRecognizer.from_sense_voice` to prevent the model from misidentifying silence/accents as Chinese tokens (`我`, `。`).

### 4. SpeechRecognizer Intent Extra ClassCastException
- **Issue**: `MainActivity.java` passed `2000L` (`Long`) for `EXTRA_SPEECH_INPUT_COMPLETE_SILENCE_LENGTH_MILLIS`, causing `ClassCastException` inside Google TTS RecognitionService which expected `Integer`.
- **Fix**: Changed constants to standard `int` (`2000`, `1500`).

### 5. SingleTask Activity Launch & UI Thread Evaluation
- **Issue**: Background intent dispatch via `am start` spawned duplicate task instances or ran off the Android UI thread.
- **Fix**: Added `android:launchMode="singleTask"` in `AndroidManifest.xml` and wrapped `evaluateJavascript` in `runOnUiThread` inside `onNewIntent`.

### 6. Default Language Selection on Call Start
- **Requirement**: In live call mode, English must be selected and active by default.
- **Fix**: Initialized `liveLang = "en-IN"` on call initiation (`liveStart()`), set `data-lang="en-IN"` pill button to active, and called `syncLiveLangUI()`. Added fallback to system Gujarati font (`Noto Sans Gujarati`) in the font family stack for clean rendering.
### 7. Multi-Turn Bilingual Live Call Test Verification
- **Test Protocol**: Clean app launch (`pm clear`), chat reset, live call initiation, 5 English turns, live language switch to Gujarati, 5 Gujarati turns.
- **English Phase (Turns 1–5)**:
  - Validated SenseVoice STT, LLM generation, Sonia TTS playback, and live caption transitions.
  - Topics covered: greetings, Ahmedabad November weather, Sabarmati Riverfront, evening activities, language handover.
- **Gujarati Phase (Turns 6–10)**:
  - Validated native `SpeechRecognizer` (`gu-IN`), Gujarati prompt execution, Gujarati assistant response, and native Gujarati TTS (`gu-in-x-guc`).
  - Topics covered: Gandhi Ashram overview, nearest railway station, Ahmedabad sightseeing, traditional Gujarati thali dishes, closing thanks.
- **Latency profile**: ~2.0s silence buffer + ~0.3s STT + ~1.8s LLM + ~0.4s TTS ≈ 4.5s end-to-end voice latency.
